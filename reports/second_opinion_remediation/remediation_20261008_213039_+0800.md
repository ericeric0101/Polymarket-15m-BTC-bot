## 3. Exact fixes

### Dry-run execution boundary

`bot/execution_safety.py::ExecutionSafetyMixin.submit_order` 是 IntegratedBTCStrategy 第一順位 public submit authority。只有明確 `test_mode is False` 且既有 dry-run checker 未宣告模擬時才轉送 framework submit。缺少／無法確認模式時 fail closed。Urgent exit 另在任何取消、建單、submit 前使用相同判斷防護。

全部四個 production submit call sites：

- `bot/order_submission.py::submit_maker_quote`：maker BUY/SELL、TP/recycle、cancel/replace 的新單。
- `bot/taker_exit.py::_submit_taker_exit_order`：market IOC／limit IOC／limit FOK。
- `bot/taker_exit.py::_submit_passive_recovery_exit`：passive recovery GTC。
- `bot/taker_exit.py::_maybe_maker_urgent_exit`：urgent SELL GTC。

AST inventory 與 production MRO assertion 覆蓋這四個 call sites，BUY/SELL maker 真實呼叫路径亦測試模式矛盾時不抵達 fake venue。Redemption 是合約結算流程，未新增 venue order submit 路径；本 patch 未改其既有模擬防護。

### Independent hard-loss protection

`bot/exit_engine.py::ExitPolicyEngine.evaluate` 移除 absolute 與 catastrophic candidate 對 STOP_LOSS 的耦合；`bot/taker_exit.py::_maybe_taker_exit_positions` 允許配置開啟的 hard breaker 進入 evaluate／確認／執行邊界。

STOP_LOSS=0 仍停用一般 adaptive/strategy loss exits、urgent strategy stop 與既有 endgame strategy gating。Absolute breaker 保留原金額、min hold、adverse trend、15s／兩 thesis votes 或 final-120s 確認；catastrophic breaker 保留原金額、有效 min hold、price adversity、thesis／opposite signal、tail 與既有確認次數，並保留既有 spread／working-SELL 等執行 gate。兩個 hard breaker 各自仍可透過既有配置停用。本機 `.env` 的 STOP_LOSS_ENABLED=0 未改。沒有調整任何風險／策略 threshold。

### Invalidation persistence

`run_bot.py::_update_side_invalidation_state` 以 shared quote-cycle timestamp、market slug、locked side 去重。三 confirmations 仍是三個 distinct cycles，沒有換算成秒數。Sibling observations 可清除矛盾／缺資料狀態但不能再加一次；market／side 變更開始新序列。只有一個 latest cycle marker，沒有新增無界 map。

### Freshness provenance

`bot/research/freshness.py` 是單一 native-v2 eligibility authority。ResearchStore snapshot／generic prediction-event／coverage readers、MarketEvidence projection、prediction_snapshot_analysis、four_market_prediction_forensics、research_analysis 的 native joins 都使用同一版本 gate。v1、missing、unsupported version 與 historical provenance 分別排除並計數。Selection reader 的統計在 stderr 輸出，不破壞 stdout JSON；integrity／prediction report 亦提供 exclusions。

Historical recomputation 明確 opt in `HISTORICAL_RECOMPUTATION_INPUT`，完成分析後標 `HISTORICAL_RECOMPUTED`；原本 version 不改寫。Native reader 不能把這些 rows 當原生 v2。Raw inventory/provenance inspection API 仍能檢視歷史 payload，但不構成 native cohort；pure analysis functions 必須由上述受限 reader 或明確 historical pipeline 提供資料。未改寫歷史 DB／Parquet，也未重跑 weekday/weekend 報告。舊資料被排除後 native cohort N 可能下降，这是正確 provenance 行為。

### Opening snapshot

`PredictionResearchSnapshotter.capture` 能在 trading 仍停留於舊市場 settlement grace 時，選取已 admitted 的 wall-open pair／該市場 strike。使用既有 quote-only prewarm BBO 及原 receipt/source clocks；不借用舊 side、score、strike 或 instrument pair。Missing strike／不完整 pair 等待；stale／future receipt 不可標 fresh。

`bot/market_runtime.py::_capture_fresh_prewarm_quote` 開盤後利用既有 maker worker／lock 觸發 research-only capture，解決舊市場沒有 QuoteTicks 就無法喚醒的邊界。沒有新增獨立 thread authority；沒有用 prewarm quote 執行 maker、promote instrument、subscribe 或修改交易 settlement grace。節流沿用 snapshot interval，停止中不啟動研究工作。

合成測試為 open+1.2s（輸入已於 open+1s 收到），目標 ≤2s。這是軟體／hermetic 證據，不是 live latency SLA；真實 readiness、worker contention、source缺資料仍可能延後。尚未啟動 bot 驗證真實第一筆 delay。
