# L2 retry state initialization fix

## Reproduction and authority

Before patch, exact real patched publisher test:
quote-only prewarm -> skipped_unsubscribed -> add existing L2 subscription ->
publish_l2_snapshot_if_due raised KeyError('retry_at') at old line919.
Test failed before source edit; passed afterwards.

State container is adapter._btc15m_l2_publish_state. It is created per client
in patched_init. Early skipped_unsubscribed and skipped_stopping previously
created {} with only last_status. Later subscribed branch/full book branch
used dict.setdefault(key, full_default), which does not fill an existing dict.
A full/reconnect snapshot also could not repair that partial record.

Now one l2_publish_state helper fills missing last_attempt/last_success/failures/
retry_at defaults before every producer uses state. Existing values, including
retry deadline and failure count, remain unchanged. No exception suppression.
No new task/thread, no subscription mutation, no retry parameter changes.
Callbacks are synchronous on adapter owner loop; initializer has no await.
Reconnect retains state; resubscribe/handoff reuses same instrument ID state.
Node rebuild initializes a new client container. No new stale-state cleanup
is introduced; removed/unsubscribed instrument cannot publish, stopping still
fences publication. Existing cache/node lifetime bounds are unchanged.
