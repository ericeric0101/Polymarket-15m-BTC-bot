# TWAP 難度 z 候選策略：forward shadow 事前登記規格 v2

寫定時間：2026-10-15 約 09:10（Asia/Taipei），在任何 v2 評估資料被分析之前。**本版取代 `plan.md`（v1）**，v1 沒有產生任何評估結果。commit 之後，本檔的規則、門檻與判讀不得修改。

## 為什麼改版

使用者決定不依賴交易 bot 的匯出（選項 2），改由獨立記錄器同時收價格與 Polymarket 盤口。資料來源改變，strike、剩餘所需平均價、波動率都必須自行重建，因此出新版本。H1、交易規則、樣本量、停止規則與判讀標準都和 v1 相同（第 4–6 節），只有第 1–3 節的資料與機制改變。

## 1. 資料與結算機制

### 1.1 資料（全部唯讀）

| 用途 | 來源 |
|---|---|
| Chainlink spot、TWAP（依 Chainlink 自己的秒分組）；Binance、Coinbase（依本機收到的秒分組） | `data/price_sources_1s/` |
| Polymarket BTC 15m 的 Up／Down 最佳買賣價，每秒一筆 | `data/polymarket_book_1s/` |
| 官方結果 | Polymarket Gamma（只用 `UP`／`DOWN`） |

不讀任何交易 bot 的匯出或資料庫。

**評估母體：** `market_start ≥ 2026-10-15T01:00:00Z` 的 BTC 15m 市場（新版記錄器在 00:51 UTC 啟動），且結束已超過 10 分鐘。

### 1.2 結算窗口（以實際資料驗證後寫定）

2026-10-15 00:51–01:00 UTC 的記錄資料中，Chainlink 在第 S 秒發布的 60 秒 TWAP 等於第 **S−62 到 S−3 秒**這 60 筆 Chainlink spot 的平均：217 個完整窗口中 152 個完全吻合（誤差約 1e-11 bps），其餘最大誤差 0.21 bps，p99 為 0.19 bps。其他窗口位置的誤差中位數都 ≥ 0.05 bps。

因此：
- **strike（Price to Beat）**＝在市場開始那一秒發布的 TWAP（`chainlink_twap60` 的來源秒＝`market_start`），而且必須在決策時點之前已收到。
- **結算價**＝在市場結束那一秒發布的 TWAP，也就是 END−62 到 END−3 秒的 spot 平均。最後 3 秒的價格不影響結果。
- `evaluate_v2.py` 的 `WINDOW_OFFSET = -62`。

部分窗口仍有最多 0.21 bps 的誤差，原因未明。另外會把重建出的結算方向和官方結果比對，作為資料品質指標一起報告。

### 1.3 決策時點可用的量（只用決策前已收到的資料）

- `required_future_avg_to_flip` = (60 × strike − 已觀測窗口秒的 spot 合計) ÷ 剩餘未觀測秒數。已觀測秒＝窗口內、不晚於決策前最後收到的 Chainlink 秒。已觀測部分中缺的秒用前一個值補，缺超過 3 秒就不可用。
- `remaining` = 剩餘未觀測的窗口秒數；為 0 時代表結果已定，主規則不適用（見第 7 節）。
- σ = 決策前最近 300 秒 Chainlink spot 的 1 秒對數報酬標準差，乘以 sqrt(365×86400) 年化；至少需要 240 筆報酬。
- 盤口：同一市場、同一 outcome，取不晚於決策時點、且相差 ≤ 3 秒的最近一筆每秒樣本。有效條件：`0 ≤ bid ≤ ask` 且 `0.001 ≤ ask ≤ 1`。
- `mid` = Up 盤口有效時取 Up 的 (bid+ask)/2，否則取 1 − Down 的 mid。

## 2. 決策網格與合格列

每個市場在 T−55、T−50 … T−5 秒做決策。合格：strike、`required_future_avg_to_flip`、`remaining > 0`、σ > 0 都可用，且至少一側盤口有效。

## 3. z 定義

`z = (S − required_future_avg_to_flip) / (S × σ × sqrt(remaining / (3 × 365 × 86400)))`

| 變體 | spot S | 角色 |
|---|---|---|
| **ZC（主要）** | 記錄器 Chainlink spot，as-of 決策時點、相差 ≤ 3 秒 | 確認性判讀只看這個 |
| ZB | Binance as-of × (1 − b̂/1e4)；b̂ = 決策前 3600 秒內，同一本機秒同時有 Binance 與 Chainlink spot 的配對，取 bps 中位數，至少 30 對 | 描述 |
| ZK | Coinbase as-of，不修正 | 描述 |

## 4. 交易規則（與 v1 相同）

1. 合格列中 `0.10 ≤ mid ≤ 0.90` 且 `|z| ≥ 2`。
2. 買 z 指向的一側，且該側盤口有效。
3. 每個市場只取時間上第一筆符合的列。
4. 以該列的 ask 買 1 股，持有到官方結算。
5. 費用 `0.07 × ask × (1 − ask)`；`net = win − ask − fee`。

敏感度（描述）：mid 範圍 [0.05, 0.95]。

## 5. 樣本量與停止規則（與 v1 相同）

- 主要分析時點：ZC 主規則選出、且有官方結果的市場數首次 ≥ 50。
- 在此之前只看資料覆蓋率與結算重建一致率，**不看損益**；`evaluate_v2.py` 會強制隱藏損益。
- 從 2026-10-15T01:00Z 起滿 21 天仍未達 50，就以當時樣本判讀，並標明「樣本不足」。
- INCONCLUSIVE 時可延長一次到 N = 100，之後一律結案。

## 6. 判讀（與 v1 相同）

令 `m` = ZC 主規則的每市場平均費後損益，`LB` = 市場層級 bootstrap（10,000 次、seed 20261015）的單側 95% 下界。

**PASS** 必須同時滿足：
1. `m > 0` 且 `LB > 0`；
2. 拿掉獲利最大的一個市場後，合計仍 > 0；
3. 任一 UTC 日的損益不超過合計的 50%；
4. 買 Up、買 Down 的比例都 ≥ 25%；
5. 延遲 1 秒的同側 ask 重算後，平均費後損益 > 0。

**FAIL**：`m ≤ 0`，候選結案。
**INCONCLUSIVE**：其他情況。

## 7. 描述性的「定局」政策（不參與判讀）

依第 1.2 節，結束前約 2 秒，結算窗口的全部 spot 都已收到，結果可以直接算出。在 T−10 到 T−1 秒每秒檢查一次，記錄每個市場**第一次**整個窗口都已收到的時點：
- 重建結算價與 strike 的差距（bps）、定局的一側；
- 該側當下的 ask（盤口樣本相差 ≤ 1 秒），以及 +1 秒的 ask；
- 差距 ≥ 0.5 bps 且有 ask 時，假設買 1 股的費後損益。

只描述「定局時還買不買得到、價格多少」，和主規則一樣受停止規則限制；之後若要把它當成策略，需要另寫事前登記的規格。

## 8. 一併報告

- 每日資料覆蓋率：市場數、合格列數、strike／所需平均價／盤口／各來源 spot 的可用比例。缺資料只計數，不補值、也不算輸。
- 重建的結算方向與官方結果的一致率。
- 每市場明細與延遲 +1 秒、+3 秒的 ask。

## 9. 限制

- 用記錄的 ask，沒有深度、排隊與成交模型。
- 記錄器只是一般網路連線，做市商收到資料可能更快。
- 電腦睡眠、斷網或重啟會造成資料缺口；缺口期間的市場因不合格而排除，不會被算進結果。
