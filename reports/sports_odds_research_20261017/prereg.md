# 事前登記：Polymarket 體育 moneyline vs Pinnacle 去抽水價（S1 v1）

**狀態：** CK 已審閱（2026-10-17）：θ = 1¢；H4 改為次要分析；期間改為 14 天加延長規則。凍結 = 本文件和第 3 節列出的程式一起 commit，該 commit 的時間記為 **T0**。
凍結前**不得**對收集到的資料執行 `sports_odds_analyze.py --unblind`。

## 1. 問題

方向 A：開賽前很久就在 Polymarket 進場，之後在 Polymarket 平倉，或持有到結算。

1. **H1（資訊）：** 在 Polymarket 價格之外，Pinnacle 的去抽水機率對比賽結果有沒有**額外資訊**？
2. **H2（收盤價值，CLV）：** 依規則在開賽前用 taker 買進，相對於**開賽前 Pinnacle 收盤的公允價**，扣掉手續費後的期望值是否大於 0？
3. **H3（Polymarket 來回）：** 同樣的進場，改在開賽前以 Polymarket 的最佳 bid 賣出（taker，再付一次手續費），淨損益是否大於 0？這就是「早買、晚賣、賺差價」能不能實際做到。

足球大熱門的結構性偏差（原 H4）改列為次要分析（第 6 節），因為它是看過開發資料後才提出的假設。

方向 B（冷門市場）在本研究只做描述，不做判定，見第 6 節。

## 3. 規則（凍結）

以 T0 commit 時的 `bot/research/sports_odds.py` 為準，凍結後不得修改：

- **比對：** 同聯賽；開賽時間差 ≤ 20 分鐘（UFC ≤ 12 小時）；兩隊都要用整個詞對上，而且分別對到不同隊；候選唯一。名稱正規化方式、通用詞清單、別名表都照該版本。
- **公允價：** Pinnacle h2h 的比例法去抽水（足球三方、其他兩方）。抽水 > 1.10 的不用。
- **token 的公允價：** 兩方市場直接用該隊的機率。足球 Yes／No 市場：YES 用該結果的機率，NO 用 1 − 該機率。
- **手續費：** `fee(p) = rate × p × (1 − p)`，`rate` 讀每個市場自己的 `feeSchedule`。
- **列的排除條件：**
  - `|fair − mid| > 0.20`（可能配錯）；
  - Pinnacle `last_update` 距離快照超過 30 分鐘；
  - 沒有訂單簿，或沒有 bid 或 ask；
  - 市場 `acceptingOrders = false`；
  - 開賽前不到 1 小時的快照不可以當**進場**快照（收盤快照除外）。

## 4. 主要檢驗

時間分組（距離開賽）：A = [72, 168) 小時，B = [24, 72)，C = [6, 24)，D = [1, 6)。

**H1（資訊）：**
- **樣本：** 每個「比賽 × 結果」一列。足球用 3 個 YES token；兩方市場只用第一個結果的 token，避免重複。快照取 C 組裡最晚的一個。
- **方法：** 對 `y ~ logit(mid) + logit(fair)` 做邏輯迴歸，標準誤依比賽分群。
- **成立條件：** `logit(fair)` 的係數 > 0，單尾 p < 0.05。
- 同時報告 Brier score、log loss（Polymarket、Pinnacle 各自），以及各時間分組的結果。

**H2（CLV，taker）：**
- **進場：** 每個 token 依時間順序檢查所有基準快照（A–D 組），取第一個 `taker_edge = fair − ask − fee(ask) ≥ θ` 的快照，用 ask 買進。θ = **0.01**。
- **每股 CLV：** `fair_close − ask − fee(ask)`。`fair_close` 是同一個 token 在收盤快照的公允價。
- **成立條件：** 平均 CLV > 0，而且 95% bootstrap 信賴區間的下界 > 0（依比賽分群重抽，10,000 次）。

**H3（Polymarket 來回）：**
- **進場：** 同 H2。
- **每股淨損益：** `bid_close − ask − fee(ask) − fee(bid_close)`。`bid_close` 是同一個 token 在收盤快照的最佳 bid。
- **成立條件：** 同 H2。

**多重檢驗：** 總共 3 個主要檢驗，各自報告，不做校正。依第 7 節判定時，要把這一點列入考量。

## 5. 樣本量與檢定力（事前估計）

- 開發掃描每次約有 120 場開賽前、已比對的比賽。NBA 例行賽開打後，加上 NHL，每天約 15–25 場。14 天內預估有 500–800 場不同的比賽可以納入。
- H2／H3 的進場頻率：開發掃描裡 `taker_edge ≥ 0.01` 的 token 大約占 1%，而且集中在歐冠的早盤。每場比賽有多個快照，預估 14 天有 50–200 筆進場，所以才訂了延長規則。
- 如果單筆 CLV 的標準差約 0.02，那麼 150 筆、扣除分群影響後，95% 信賴區間的半寬約 ±0.004。H2 的檢定力夠。H3 會受價差影響，標準差預估 0.03–0.05，檢定力比較低。
- H1：公允價和中間價高度相關（中位數只差 0.6¢），所以 H1 的檢定力**偏低**。H1 不成立**不等於**證明 Pinnacle 沒有資訊。

## 6. 次要分析（只描述，不用於判定）

- **θ 的敏感度：** θ ∈ {0.005, 0.02, 0.03}。
- **足球大熱門（原 H4）：** 足球聯賽（含 elc）中，取第一個符合 `fair ≥ 0.65`、距離開賽 ≥ 24 小時的「球隊 YES」快照，每個 token 一列。報告 `mid − fair` 的平均，以及 95% 分群 bootstrap 信賴區間。這個偏差來自開發掃描的觀察：最大的優勢集中在歐冠的「和局 YES」和「大熱門 NO」。
- **手續費的敏感度：** 改用 `p × rate × p(1−p)`（`execution/rebate_model.py` 的寫法）。
- **持有到結算：** 進場同 H2，每股損益 = `y − ask − fee(ask)`。
- **H2／H3 依時間分組（A–D）、依聯賽分組。** 特別要看 A 組（≥ 72 小時）是不是只有歐冠和歐聯才有。
- **方向 B：** 探索聯賽（elc、shl、liiga）和主要聯賽比較：`|fair − mid|` 的分布、進場頻率、可成交的正期望值金額（`plus_ev_usdc`）、比對率。
- **容量：** 每筆進場的 `plus_ev_usdc` 分布、每天加總，看這個策略一天最多能放多少錢。
- **Pinnacle 本身的移動：** `fair_close − fair_entry` 的平均和分布。用來分辨「Polymarket 往 Pinnacle 靠」和「兩邊一起移動」。
- **其他博彩公司：** 用 Betfair、Matchbook 的價格當公允價，重算 H2。
- **maker：** 只記錄 `fair − bid`。沒有成交資料，**無法**判斷 maker 能不能成交，不在本研究判定範圍內。

## 7. 判定

| H2 | H3 | 下一步 |
|---|---|---|
| 成立 | 成立 | 寫 forward 紙上交易的事前登記（taker 早進場、收盤前在 Polymarket 平倉） |
| 成立 | 不成立 | Polymarket 會收斂，但價差和手續費吃掉了來回的利潤。評估兩條路：持有到結算（看次要分析），或進場改成 maker |
| 不成立 | — | 「早盤用 taker 進場」的方向結案 |

- **足球大熱門偏差（次要分析）：** 如果平均 > 0 而且信賴區間下界 > 0，另寫一份事前登記，用新的 forward 資料驗證，之後才能設計策略。
- **H1：** 只作為輔助證據，不單獨決定下一步。
- **方向 B：** 如果探索聯賽的 `|fair − mid|` 分布和進場頻率沒有明顯比較高，就不再擴大到更冷門的市場。
