# TWAP-z 尾段執行器：P1 規格與 P2 小額 live 條件

狀態：**已確認**（2026-10-16 09:30 台北）。使用者同意採用獨立程序架構，以及 P2 預設金額。commit 之後，不得依結果修改。

## 0. 和其他計畫的關係

- **交易規則**完全沿用 `reports/twap_z_forward_shadow_20261015/plan_v2.md` 第 2–4 節，只看主要變體 ZC。這份規格只規定「怎麼下單」，不改規則、門檻、樣本量或判讀。
- shadow v2 的判讀不變：以記錄器資料、ZC 達 N ≥ 50 為準。
- 執行器的真實成交是**另一個量測**，不併入 shadow v2 的損益計算。

## 1. 架構（建議）

**獨立程序**，和記錄器同一個架構，不放進 Nautilus 交易 bot：
- **資料來源：** 直接訂閱 RTDS Chainlink（spot + TWAP）、Polymarket 盤口 WS、Gamma 市場清單，和記錄器同一套解析程式。
- **為什麼不放進 bot：**
  - 決策延遲不受 bot 的 rollover、fee lookup 和 event loop 負載影響；
  - 不碰受保護的決策模組；
  - Entry V3 DRY-RUN 可以照常平行跑。
- **下單：** 使用 repo 內的 `py_clob_client`；fee rate 在市場開盤時預抓。
- **P0 的定位：** P0 的修復仍然有價值，因為 bot 本身和它的 HOLD／TP 路徑也受益；但它們不再是這個執行器的前置條件。

## 2. 決策（與 plan_v2 相同）

- 每個市場在 T−55、T−50 … T−5 秒評估一次。
- 條件：strike、所需未來平均價、σ、盤口都可用；`0.10 ≤ mid ≤ 0.90`；`|ZC| ≥ 2`。
- 買 z 指向的一側；每個市場只取第一筆符合的列。

## 3. 下單

| 項目 | 規定 |
|---|---|
| 委託 | limit = 決策當下該側的 best ask，**FAK**（能成交多少就成交多少，其餘立即取消）。不追價、不重試 |
| 數量 | 5.5 股（交易所最小 5 股，加上手續費緩衝），只在 P2 使用 |
| 持有 | 持有到結算，沒有任何 SELL。結算後自動 redeem |
| fail-closed（不下單） | Chainlink spot 或 TWAP 的接收年齡超過 3 秒；WS 斷線；strike 還沒 final；盤口 WS 超過 5 秒沒有任何訊息，或該 token 沒有本連線的完整 snapshot（盤口在報價沒變動時本來就不會更新，所以不以單一 token 的更新年齡判斷）；fee 未知；同一個市場已經有部位；已觸發當日或累積虧損上限 |

## 4. P1：DRY-RUN（1–2 天）

**只量測，不送單：** 每次觸發都記錄 would-submit。

| 指標 | 進入 P2 的條件 |
|---|---|
| 決策 → 送單前的延遲 | p99 < 500 ms |
| 與記錄器 shadow（evaluate_v2）的觸發一致率 | 同市場、同側、同時點 ≥ 90%（以 coverage 計，不看損益） |
| fail-closed 的原因分布 | 全部有原因碼；沒有 fail-open |
| 程序穩定性 | 沒有 crash，WS 都能自動重連 |

**P1 不看損益。** 損益只在 shadow v2 達到 N ≥ 50 時，依 plan_v2 判讀。

## 5. P2：小額 live（金額已確認）

| 參數 | 建議預設 | 使用者決定 |
|---|---|---|
| 每筆股數 | 5.5 | ✔ |
| 單日虧損上限（達到就停到隔日） | $15 | ✔ |
| 累積虧損上限（達到就停，回報） | $50 | ✔ |
| 同時持倉 | 每市場 1 筆 | — |
| 結束條件 | shadow v2 判讀時，或累積上限 | — |

**P2 量測：** 真實成交率、成交價和決策時 ask 的差、成交延遲。

**P2 不得：** 改規則、調整門檻、加大股數。放大部位只能在 shadow v2 PASS 之後，另寫規格決定。

**LIVE 由使用者啟動。**

## 6. 一致性規則（實作細節）

- **何時算「已選」：** 一個 checkpoint 只要符合 plan_v2 規則，該市場就算已選，即使執行器因為 fail-closed 沒有下單；之後的 checkpoint 也不再交易。這樣執行器選的市場和時點，不會比 shadow 多。
- **核心機制驗證：** `verify_replay.py` 用記錄器 10/15–10/16 的資料重播，1,078 個 checkpoint 的 strike、所需平均價、σ 和 spot，與 `recorder_mechanics.ChainlinkSeries` 完全一致（0 筆不一致）。
